## Backlog — HIGH (data loss / node down / money stranded)
- **B-DB1** `startTransaction`/`endTransaction` are not exception-safe: a throw
  mid-block leaves `_transactionDepth ≥ 1` with `BEGIN` open, so **nothing ever
  commits again** until restart (silent data loss, unbounded WAL). *Fix:* RAII
  transaction guard, or reset depth + `ROLLBACK` in the analyzer's recovery catch.
  `src/Database.cpp:852-887`, `ChainAnalyzer.cpp:491`.
- **B-INST1** Service-mode DigiByte auto-update stops the wallet and never
  restarts it (a SYSTEM task can't launch the GUI into the user session) → node
  offline until next logon; also `Stop-DigiByteGracefully` waits on `digibyted`
  (never running) and the NSIS exit code isn't checked. `setup-digiasset.ps1:1747,614,605`.
- **B-POOL1** One checksum-invalid payout address fails the whole atomic
  `sendmany` and strands every recipient, recurring each period.
  `isValidDgbAddress` is charset-only. *Fix:* validate each address via Core
  `validateaddress` and skip invalid ones (like the dust floor) before the batch.
  `PoolDashboard.cpp:109,619`.

## Backlog — MEDIUM
- **B-DB2** `clearBlocksAboveHeight` (reorg rollback + startup repair) is
  non-atomic and swallows errors → tables left mutually inconsistent. Wrap in a tx.
- **B-DB3** Reorg rollback resets `heightDestroyed` but not `spentTXID` → dangling
  txids in asset history. `Database.cpp:1504`.
- **B-DB4** Unsynchronized RAM caches (`_utxoCache*`, `_flagState`,
  `_exchangeWatchAddresses`, `_masterDomainAssetId`) raced between analyzer and
  RPC/web threads (UB). Guard each with a mutex.
- **B-DB5** `getAssetUTXO` wallet fallback indexes `vout[]`/`addresses[0]` with no
  bounds check → crash/DoS from a crafted RPC call. `Database.cpp:1791`.
- **B-NET1** WebServer has no socket read/write timeout and is single-threaded →
  one idle localhost connection wedges the whole dashboard. Add SO_RCVTIMEO/SNDTIMEO.
- **B-NET2** `RPC::Server::parseRequest` reads headers with one 1024-byte
  `read_some` → intermittent "No request body found" on split/large headers. Loop.
- **B-NET3** No SO_SNDTIMEO on the RPC socket → a client that never reads its
  reply pins a worker thread (N such = RPC wedged, incl. `sendtoaddress` forwarding).
- **B-NET4** `getHeader` does an unanchored substring match (header confusion).
- **B-NET5** `CurlHandler` download/postJson error paths don't `discardHandle()`
  and leave a truncated temp file on disk.
- **B-POOL2** Discovered-pool `nodes[]` JSON spliced verbatim into public
  `/pool/stats.json` (broken JSON / stored XSS on the landing page). Parse+escape+cap.
- **B-POOL3** On-chain-announce thread locks the wallet with no mutex vs the payout
  path → spurious payout `-13` failures. One process-wide wallet mutex.
- **B-POOL4** Ledger writes aren't transactional; if all rows fail the period guard
  stays stale → operator can re-run and double-pay. Durable guard row pre-broadcast.
- **B-INST2** `Install-DigiAsset` overwrites the live exe with no MZ/size
  validation, backup, or atomic swap (a 404/HTML body bricks the node). Mirror
  `update-node.ps1`.
- **B-INST3** Re-run can clobber a partial `digibyte.conf` and never re-syncs
  diverged RPC creds → "DigiByte Core down".
- **B-INST4** `provision-peer-pool.ps1` peer token uses non-crypto `Get-Random`.
- **B-INST5** `verify-peers.ps1 -TestAnnounce` calls undefined `Say` → crashes.
- **B-INST6** `setup-pool.ps1` node sub-install doesn't pass `-PoolServer` → pool
  box's own node points at the public pool, and it blocks on interactive prompts.
- **B-INST7** Config files (`digibyte.conf`/`config.cfg`/`pool.cfg`) written
  world-readable; contain rpc/pool/wallet secrets. `icacls` to admins/SYSTEM.
